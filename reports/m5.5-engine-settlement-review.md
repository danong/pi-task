## Verified contract behavior

### Runtime schemas and authority

`WorkspaceFinalizationSchema` is strict, requires nonempty provider-neutral identities and path entries, and rejects `hasChanges`/`changedPaths` disagreement. `CombineOutcomeSchema` is strict and validates identity, conflict list, and nonnegative integer count. Both import only `zod`; neither references a provider implementation, and `acceptance.ts`/`settlement.ts` are provider-free. A malformed finalizer is converted to a worker failure before receipt derivation; malformed combine evidence is caught by the merge fence.

**Combine evidence is the aggregate authority for engine settlement.** For an engine-derived aggregate, `acceptArtifacts` receives the raw `combineOutcome.changedPaths/presentFiles/deletedFiles` values, not a normalization: missing (`undefined`) or `null` evidence produces `authoritative_evidence_missing`; explicitly empty `presentFiles` (or any deleted/absent inconsistency) produces `authoritative_evidence_insufficient`; `hasIntegratedChange` is derived from the same list so it cannot disagree. There is no fallback to per-worker finalization or model claims on the engine-derived path — the prior `length > 0` substitution is gone (`parallel.ts:1312-1335`). The real jj driver always supplies all three combine lists (`jj.ts:522-561`), and the removed-evidence regression (`test-parallel.ts`) proves a provider omitting them fails closed.

The engine-derived settlement type requires `summary: null`, `deviations: null`, and forbids a `Yield` (`settlement.ts` staged discriminated union); engine receipts carry measured observed turns/usage and `settlementSource: engine_derived`. Acceptance rejects missing/inconsistent engine tree evidence, required-file deletion, failed verification, invalid paths, and missing commit identity (`test-acceptance.ts`, `test-contracts.ts`, `test-trace.ts`).

### Prompt and watchdog lanes

The public CLI standalone lane makes exactly **one** prompt and observes the original settle (`test-cli.ts` no-yield case, `promptCalls === 1`); the direct isolated runner does the same (`test-parallel.ts:596-634`; `test-watchdog-driver.ts:374-388`). Retained M5 child work passes `retainWorkspace: true →` default nudge and its prior watchdog semantics; multi-worker runs (not `singleTask`) also keep the nudge. `test-sequential.ts` passes and exercises the child continuation lifecycle. One boundary fact is recorded below: the M5 sequential **parent** (via `prepareSequentialChild` → `runIsolatedTask`) also resolves to the isolated lane because it does not set `retainWorkspace`; this is within the milestone-2 `runIsolatedTask` boundary and does not alter M5 child/edge semantics.

### Objective gates, preservation, and synthesis

Returned verification failure, the materialization exception, and the verification-driver exception all become non-ship terminal failures through the same `failObjectiveGate` fence. Ordinary merge/conflict/acceptance failures preserve workspaces and reconcile once (the materialization test counts one recovery and a terminal failed ledger task). No settlement path creates a model summary, deviations, or a synthetic Yield, and receipts/traces carry measured (or explicitly `unavailable`) usage only. Existing sequential tests pass including parent/child artifact and lifecycle checks; no M5 sequential regression was observed.

## Current findings (prioritized)

No C1 or C2 findings remain. The following are C3 evidence/hardening gaps; none creates a ship-without-authority, premature-ship, or wrong-authority path, and each is a mechanical composition of already-tested behavior.

### C3 — Runner-level cancelled/rejected event regression is absent

The unified `terminalDisposition` machinery (`parallel.ts:724-735`) is new, and the engine predicate excludes `error|cancelled|rejected` dispositions by construction. `test-watchdog-driver.ts` proves observe-mode settle yields no nudge, and the failed-verification and absent-finalization tests prove non-candidates fail. There is no full-runner regression that emits `cancelled` then `settled` (or `rejected` then `settled`) through a fake host and asserts non-ship. This is optional hardening; the predicate is trivially order-safe (only an event sequence with no terminal fact other than `settled` can be a candidate).

### C3 — Standalone terminal-trace-write failure corner is untested

The rollback branch at `cli.ts:1109-1131` (final ship receipt already durable; the last terminal ship trace write fails → rollback receipt rewritten failed, delivery_pending returned) has no standalone test; the fault-injected final-receipt tests cover the preceding stage and the sequential edge outbox covers the edge variant. Worst case even if the rollback receipt write also failed, the ledger remains `delivery_pending` and the durable trace remains `failed`; nothing ships. Optional regression hardening.

### C3 — Thrown verification driver and malformed fulfilled finalization regressions

`failObjectiveGate` is exercised by the materialize-throw test but not by a returning-throw from `verifyThroughEnvironment`; a schema-invalid (but fulfilled) finalization is not injected at the runner level (the absent-finalizer and combine-evidence tests cover the same `finalizationErrors`/fence mechanics). Both are the identical already-reviewed fence; optional hardening.

### C3 — Minor attribution/observability nits

- A fulfilled prompt with a `cancelled` or `rejected` disposition fails as "settled without yield" in the failure-artifact cause even though it was cancelled/rejected (non-ship either way; label could name the actual disposition).
- A failed provisional receipt retains `settlementSource: "engine_derived"` metadata on a delivery-failure return; verdict governs ship truth, so this is informational only.

### Boundary observation — M5 sequential parent is inside the isolated lane

`prepareSequentialChild`'s parent call (`sequential.ts:487-493`) uses `runIsolatedTask` without `retainWorkspace`, so it now selects observe-mode watchdogs and can engine-settle a no-yield parent when finalization/combine/verification/acceptance all pass. The retained M5 **child** (`retainWorkspace: true`) and multi-worker lanes are unchanged, no M5 edge/ledger/handoff semantics changed, and `test-sequential.ts` is green. The previous review's milestone-2 boundary explicitly includes "standalone no-yield settlement through `runIsolatedTask`", so this is a documented boundary fact rather than a blocker; if a future milestone wants the M5 parent to keep the nudge, the lane predicate (or the parent call) is the single seam to adjust.
